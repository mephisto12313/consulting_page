## 1. Паспорт проекта

### 1.1. Продукт

Продающий сайт консалтингового бюро по развитию территорий и разработке девелоперских архитектурных продуктов.

### 1.2. Цели сайта (равноценные)

1. **Заявка / короткий бриф** — квалифицированный запрос на консультацию или проект.
2. **Звонок / обратный звонок** — быстрый контакт без длинной формы.

Остальные цели (узнаваемость бренда, демонстрация экспертизы) подчинены этим двум CTA.

### 1.3. Целевые сегменты

| Сегмент | Что ищет на сайте |
|--------|-------------------|
| Собственник недвижимости | Стратегия актива, аудит, упаковка, best-use |
| Девелопер / застройщик | Продукт, ГП/концепция, исследования, сопровождение |
| Управляющая компания | Сервисная концепция, стандарты, эксплуатация |
| Estate-брокер | Упаковка объектов, аналитика, материалы для продажи |
| Инвестор | Аудит объектов, due diligence, исследования |
| Государство | Территориальное развитие, конкурсы, стратегии |

Сегменты используются в блоке «Для кого» и в поле статуса брифа — **не** как шесть равноценных карточек в hero.

### 1.4. KPI MVP

- Количество заявок (бриф + форма звонка)
- Количество кликов по телефону (`tel:`)
- Доля завершённых брифов от начатых
- Глубина просмотра: Услуги / Кейсы

### 1.5. Вне скоупа MVP

Estate-витрина, магазин исследований, сервисы/стартапы, Instagram-лента, длинный квиз (до 16 карточек), корзина услуг — см. [раздел 11](#11-этап-2-вне-mvp).

## 3. Принципы компоновки (эталон)

Сверка ведётся по принципам продающего B2B-сайта, а не по копированию чужой структуры.

### 3.1. Обязательные правила

1. **Одна композиция первого экрана** — не дашборд: бренд, один заголовок, одна поддерживающая фраза, одна группа CTA, один доминирующий visual.
2. **Brand test** — если убрать навигацию, первый экран всё ещё должен однозначно принадлежать `{{BRAND}}`.
3. **Hero budget** — в первом viewport нет статистики, расписаний, адресов, промо-стикеров, вторичных блоков.
4. **Full-bleed hero** — визуал edge-to-edge (фото/видео среды или проекта), без inset-карточек и коллажей в hero.
5. **No cards in hero** — карточки допустимы только там, где они обслуживают выбор/действие.
6. **One job per section** — у секции одна цель, один заголовок, обычно одно короткое пояснение.
7. **Proof before catalog** — доказательства (цифры, логотипы, кейсы) раньше длинных списков услуг.
8. **CTA без e-commerce** — нет корзины и «запомнить»; действие = «Обсудить» / «Оставить заявку» / «Позвонить» / «Перезвоните».
9. **Короткая форма** — бриф ≤ 6 шагов, суммарно ≤ 8 обязательных полей до отправки контактов.
10. **Motion с целью** — минимум 2–3 осознанных движения (см. [раздел 7](#7-визуальная-система-принципы)).

### 3.2. Антипаттерны (запрещено в MVP)

- Фиолетовые / indigo gradient-темы «из коробки»
- Тёплый cream-фон + terracotta + дефолтный serif-контраст
- Газетная вёрстка: волосяные линии, нулевой радиус, плотные колонки
- Перегруз glow, rounded-full pills, многослойные тени, эмодзи как декор
- Dashboard-сетки на главной
- Наложение бейджей и стикеров поверх hero-медиа

## 5. Глобальный каркас

### 5.1. Header

| Элемент | Поведение |
|---------|-----------|
| Логотип `{{BRAND}}` | Ссылка на `/` |
| Меню | Услуги → `/services`; Кейсы → `/cases`; О нас → `/about`; Контакты → `/contacts` |
| Телефон `{{PHONE_PROJECT}}` | `tel:` на мобильных |
| CTA primary | «Оставить заявку» → `/contacts#brief` |
| CTA secondary | «Позвонить» / «Перезвоните» → `/contacts#callback` или `tel:` |
| Соцсети | Иконки Telegram / YouTube / Instagram (ссылки наружу) |

**Не включать в header:** корзину, «звезду», кнопку «Заполнить бриф» как отдельный шумный элемент рядом с двумя CTA (бриф доступен через «Оставить заявку»).

На mobile: бургер-меню; телефон и один primary CTA остаются видимыми.

### 5.2. Footer

- Навигация по страницам MVP
- `{{ADDRESS}}`
- Три линии контактов: проект / сотрудничество / образование (телефон + email)
- Соцсети
- Копирайт `{{BRAND}}`

**Не дублировать** в футере длинную статистику — цифры живут в proof-блоке на главной.

## 6. Постраничные спецификации

### 6.1. Главная `/`

**Цель страницы:** за 15–30 секунд понять, кто вы, для кого, чем сильны, и оставить контакт.

| # | Блок | Job | Контент | Действия |
|---|------|-----|---------|----------|
| 1 | **Hero** | Узнавание + вход | Full-bleed visual (город / объект / среда). Бренд `{{BRAND}}` как hero-level сигнал. Один headline (напр. «Программируем будущее территорий»). Один support: `{{BRAND_TAGLINE}}`. CTA: «Оставить заявку» + «Перезвоните» / «Позвонить» | Скролл дальше; CTA на `/contacts` |
| 2 | **Для кого** | Сегментация | 6 сегментов компактно (иконка/подпись + 1 строка выгоды). Без PDF в этом блоке на MVP | Клик по сегменту → `/services?audience=…` или якорь кластера |
| 3 | **Направления услуг** | Ориентация | **4–6** направлений (не 25). Пример кластеров — см. [6.2](#62-услуги-services) | «Все услуги» → `/services`; пункт → якорь/карточка |
| 4 | **Proof** | Доверие | 3–5 метрик (продукты / эксперты / проекты / девелоперы — контент заполнить) + логотипы клиентов при наличии | Без обязательного клика |
| 5 | **Избранные кейсы** | Доказательство экспертизы | 3–6 кейсов: фото, название, вклад бюро в 1 строку | «Подробнее» → `/cases`; «Все кейсы» |
| 6 | **CTA-полоса** | Конверсия | Короткий текст + форма обратного звонка (имя, телефон, удобное время) **или** две кнопки на `/contacts` | Отправка формы / переход |
| 7 | Footer | Служебно | Как в §5.2 | |

**Hero — запрещено:** второе видео-окно, блок «брендинг названия» внутри обложки, Telegram как третья равноценная CTA, стикеры поверх медиа.

**Mobile:** hero сохраняет иерархию; сегменты — горизонтальный скролл или 2 колонки; кейсы — одна колонка.

### 6.4. О нас `/about`

**Цель:** доверие к людям и позиции бюро. Контакты вверху страницы **не ставить**.

| # | Блок | Содержание |
|---|------|------------|
| 1 | Миссия | Крупное фото команды/среды + текст миссии (контент написать) |
| 2 | Ядро команды | Сначала **лидеры / ключевые роли** (не 13+ равных карточек сразу). Поля: фото, ФИ, должность, 1–2 компетенции, ключевые проекты (из анкет) |

### 6.5. Контакты и бриф `/contacts`

**Цель:** два ясных пути без корзины и без 16-шагового квиза.

#### Путь A — «Перезвоните» (`#callback`)

Поля:

1. Имя  
2. Телефон (обязательно)  
3. Удобное время (опционально: селект или свободный текст)  
4. Комментарий (опционально)

Кнопка: «Жду звонка».  
Рядом: кликабельный `{{PHONE_PROJECT}}` и `{{EMAIL_PROJECT}}`.

#### Путь B — «Короткий бриф» (`#brief`)

Не более **6 шагов**, суммарно не более **8 полей** до отправки:

| Шаг | Содержание |
|-----|------------|
| 1 | Статус клиента (6 сегментов) |
| 2 | Роль / должность заполняющего (короткий список или текст) |
| 3 | Тема / интересующее направление (кластер или услуга; может прийти из `?service=`) |
| 4 | Объект и локация (опционально; можно «пока нет данных») |
| 5 | Краткое описание задачи (textarea) |
| 6 | Контакты: имя, телефон, email; файл (опционально); согласие на обработку ПДн |

На каждом шаге: «Пропустить» / «Нет данных» где уместно; всегда виден прогресс и кнопка «Сразу к контактам».

#### Общий блок страницы

- `{{ADDRESS}}`
- Три линии контактов (проект / партнёрство / образование)
- Соцсети

**Ошибки исходного Excel, которые здесь исправлены:** нет корзины сохранённых услуг; нет 16×15 полей; нет обязательного ветвления на 20+ карточек.

## 7. Визуальная система (принципы)

Не макет, а рамка для дизайна.

### 7.1. Направление

Архитектурно-урбанистическое: спокойная нейтральная база (светлый камень / тёплый серый / графит), **один** акцентный цвет (не фиолетовый), много воздуха, крупная проектная фотография как главный носитель смысла.

### 7.2. Типографика

- Выразительная пара: display + text (не Inter, не Roboto, не Arial, не system-ui как единственный стек).
- Бренд в hero визуально сильнее или равен headline, не мельче «eyebrow».
- Длинные тексты услуг — читаемый размер, комфортная мера строки.

### 7.3. Медиа

- Hero: full-bleed изображение или короткий loop ≤15–20 с; тяжёлое «видео до 10 минут» — только по отдельной кнопке «Смотреть презентацию» **ниже** первого экрана или в модалке, не внутри hero budget.
- Кейсы и услуги: реальные объекты/среда, не абстрактные градиенты как единственный visual.

### 7.4. Motion (минимум 2–3)

1. Лёгкий motion в hero (kenburns / fade медиа или параллакс текста — без шума).  
2. Scroll-reveal секций (opacity/translate, коротко).  
3. Hover на кейсах / направлениях (масштаб фото или underline).

### 7.5. CSS-переменные (задать в дизайн-системе)

```text
--color-bg
--color-surface
--color-text
--color-muted
--color-accent
--font-display
--font-body
--space-section
--radius-control   /* только для интерактивных контролов */
```

Карточки — только для интерактива (выбор сегмента, услуга, кейс). Если border/shadow/radius не помогают пониманию — убрать.

## 9. Нефункциональные требования (кратко)

- **Адатив:** корректная работа desktop и mobile; touch-цели ≥ 44px.
- **Производительность:** LCP hero под контролем (оптимизация изображений, poster для видео).
- **Доступность:** контраст текста, фокус у форм, `alt` у смысловых изображений, управление брифом с клавиатуры.
- **Формы:** клиентская валидация; таймаут запроса к серверу **10 секунд**; понятное сообщение об ошибке/успехе; логирование ошибок отправки на стороне интеграции.
- **Аналитика:** события на отправку callback, отправку брифа, клик `tel:`, открытие услуги/кейса.
- **Юридика:** согласие на ПДн, политика конфиденциальности (ссылка в формах).

Стек разработки в этом ТЗ **не фиксируется**.

## 11. Этап 2 (вне MVP)

Детально не проектируется; зафиксировать как бэклог:

1. **Исследования** — рубрики, карточки материалов, сценарий «заказать исследование», схема «Бриф → КП → Договор → Старт» (без полноценного магазина на старте этапа).
2. **Estate-продукты** — витрина объектов (здания / участки / коммерция).
3. **Сервисы, инструменты и стартапы** — витрина приложений/виджетов.
4. **Пакетные услуги по статусу клиента** — переключатель сегмента → набор пакетов.
5. **Длинный квиз-бриф** (если понадобится) — только после проверки конверсии короткого брифа.
6. **Сотрудничество** — отдельная квиз-форма и витрина практикующих специалистов.
7. **Instagram / соцлента** на главной.
8. **PDF-презентации** по типам клиентов.
9. **Корзина услуг** — не рекомендуется; пересмотр только по отдельному решению заказчика.

## 12. Критерии приёмки MVP

- [ ] Пять страниц из карты сайта существуют и связаны меню.
- [ ] Первый экран главной проходит brand test и hero budget.
- [ ] На главной нет сетки из 25 услуг и нет корзины.
- [ ] Есть proof-блок и блок избранных кейсов.
- [ ] Услуги сгруппированы в кластеры; у услуги есть «Обсудить» с передачей темы в бриф.
- [ ] `/contacts` содержит путь «Перезвоните» и короткий бриф (≤6 шагов).
- [ ] Визуальные принципы §7 соблюдены (нет антипаттернов §3.2).
- [ ] Контакты и бренд вынесены в переменные / единый конфиг.
- [ ] Формы обрабатывают таймаут 10 с и показывают статус пользователю.
